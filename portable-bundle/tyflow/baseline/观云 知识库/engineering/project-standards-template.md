# 观云 React 前端项目级约定模板

## 0. 文档元信息

- 文档定位：为具体项目编写项目级约定时使用的模板与建议骨架。
- 适用范围：观云 React 前端项目需要补充仓库级规则时。
- 推荐优先级：当目标仓库缺少项目级规范时，可基于本文件裁剪生成项目自己的约定。
- 冲突处理：若与目标仓库已存在的真实写法冲突，以目标仓库已有规范与代码为准。
- 最后更新时间：2026-05-25

## 1. 文档定位

- 本文档承载“项目特有约定”的模板，用于补充公司级前端规范。
- 原则：公司级文档定基线，这里沉淀各项目会变化的实现细节。
- 使用方式：复制本模板后，结合目标仓库真实目录、请求层、组件层和样式体系进行裁剪。

---

## 2. 开工前确认项

- 拿到需求后，不要直接开始改代码；先确认当前需求对应的开发环境和交付形态。
- 开发环境、基础分支、基础 Tag、需求分支创建流程统一参考：[environment-and-branching.md](./environment-and-branching.md)
- 至少确认：
  - 当前是 `SaaS` 还是私有化发包开发。
  - 当前需求对应的基础分支或基础 Tag 是什么。
  - 本次需求开发分支应该基于哪里创建。
- 如果这些信息未确认，默认视为阻塞项；先确认，再开始开发。

---

## 3. 目录与命名约定

- 页面入口：`src/pages/<domain>/index.tsx`
- 页面私有配置：`config.ts`
- 组件目录：`PascalCase`
- 组件主文件：`component.tsx`
- 组件导出：`index.ts`

---

## 4. 请求层约定

- 所有请求函数放在 `src/services/*`，页面不直接调 `request(...)`。
- 公共前缀统一由 `src/services/core.ts` 管理。
- 页面只消费 service 返回结果，不直接拼接底层协议细节。

### 4.1 接口状态与页面态（项目实现约定）

- 页面请求状态建议统一为：`success / empty / error`。
- 页面空态可统一使用 `emptyFieldData` 类型。
- 页面错误态可统一使用 `emptyError` 类型。
- 请求结束后 `loading` 统一在 `finally` 收口（或等价统一收口逻辑）。

---

## 5. 查询构造约定

- 聚合与明细查询优先复用现有查询构造工具。
- 通用查询参数（时间、应用、实体、过滤）统一合并，不在页面重复手写。
- 新增查询结构时，优先抽到工具层而非散落在页面组件。

---

## 6. 状态管理约定

- 跨页面共享状态走全局 model/store。
- 页面筛选上下文统一通过公共上下文获取。
- 页面内部临时状态优先本地管理，不上提全局。

---

## 7. 样式落地约定

- 样式落位先看项目已有约定，不要一上来就新建局部样式文件。
- 全局样式文件仅放 reset、公共工具类、语义类、稳定复用样式与 token 映射。
- 页面私有样式放页面目录，组件私有样式放组件目录。
- 优先复用已有公共样式（公共类/公共组件样式）。
- 无法复用时，在当前页面或组件内新增局部样式，并遵循 [前端设计规范](../design/design-overview.md)。
- 仅在“跨页面复用场景明确且稳定”时，才将样式沉淀到全局。

### 7.1 样式使用方式

推荐顺序：

1. 先查项目中的 `global.less` 或等价全局样式文件，确认是否已有可直接复用的公共类、语义类或全局样式能力。
2. 如果 `global.less` 已经支持当前场景，优先直接复用，不要重复在页面内再写一套局部样式。
3. 如果全局样式不支持，或者当前样式只对单个页面/单个组件生效，再新增局部样式文件。
4. 页面局部样式默认使用当前目录的 `index.less`，并通过 CSS Modules 方式引入：

```tsx
import styles from './index.less';
```

5. 页面或组件内部优先通过 `styles.xxx` 使用局部类名，避免依赖无边界全局类名。
6. 如果某段局部样式后续被多个页面稳定复用，再评估是否上提到 `global.less` 或公共样式层。

### 7.2 适用判断

- `global.less`：适合稳定复用的公共类、语义类、全局工具类、全局覆写、token 映射。
- 页面 `index.less`：适合只对当前页面生效的布局、卡片、表格区域、筛选区等页面私有样式。
- 组件目录样式文件：适合只对当前组件生效、且组件可能被页面内部多处复用的样式。

### 7.3 禁止事项

- 明明 `global.less` 已有同语义样式，还在页面里重复写一套局部样式。
- 把页面私有布局样式直接写进全局文件。
- 页面局部样式不做作用域隔离，直接依赖裸全局类名拼装页面结构。

## 8. 组件库使用约定

- 组件选型优先级：
  1. 团队已有业务组件（项目内已封装组件或听云组件库）
  2. `antd` 官方组件
  3. 基于现有组件封装
  4. 新增自研组件
- 新增自研组件时需说明：
  - 为什么不能复用现有组件
  - 与现有组件的能力差异
  - 是否具备跨页面复用价值
- 避免以下情况：
  - 重复封装已有能力
  - 页面私有组件持续堆积并演化为“野生组件库”

## 9. 提交与门禁约定

- 提交前至少保证：
  - lint 通过
  - i18n 扫描通过
  - 关键路径测试通过
- commit message 走统一格式：
  - `<type>(<scope>): <summary>`

### 9.1 项目命令口径

- 依赖安装命令：`pnpm install`
- 本地开发命令：`npm start`
- 构建命令：`npm run build`
- i18n 扫描命令：`npm run scan`

---

## 10. 维护规则

- 项目升级或流程变化时，优先更新本文件。
- 不在本文件重复公司级通用条款，保持简洁可执行。
