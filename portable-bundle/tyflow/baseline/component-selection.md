# 组件选型基线

开发过程中选择和使用组件时必须遵守的约束条件。本文件不是流程规则，而是组件层面的事实标准。

## 接入顺序

1. 先在目标项目中查同类页面、同类组件、同名组件引入、局部二次封装或业务封装。
2. 如果项目已经使用过组件库组件，优先仿照项目里的真实用法接入（import 路径、外层容器、样式类、字段转换、ref 使用、缓存命名、空态/加载态处理）。
3. 如果项目有二次封装，优先使用二次封装，不要绕过封装直接引入原始组件（除非能说明封装不适用）。
4. 如果项目没有用过，再查组件库文档和组件库源码，按原始方式接入。
5. 只有复用成本明显高于收益时，才新增页面局部组件。

## 落地要求

- 引入组件前写清楚"为什么用这个组件"。
- 复用判断必须记录：项目内是否已有用法、是否存在二次封装、最终采用哪种接入方式。
- 接口字段映射不明确时，不允许为了套组件猜字段。
- 图表和拓扑必须先确认数据结构能否适配已有组件。

## 决策表

| 需求场景 | 优先组件 | 不建议 |
|----------|---------|--------|
| 普通业务列表页 | `TyPageContainer` + `TyTable` | 从零搭布局和表格 |
| 表格列宽拖拽/记忆 | `TyTable` | 原生 antd Table 手写拖拽 |
| 用户配置显示列 | `TyCustomTableHeader` + `TyTable` | 页面内自己维护 `localStorage` |
| 简单关键词搜索 | `TySearch` | 为一个输入框上复杂筛选组件 |
| 多维筛选/字段值筛选 | `TyFilterSelect` | 手写复杂 tag 输入框 |
| 查询时间范围 | `TimeRangePicker` | 自己拼 DatePicker + 粒度 + 缓存 |
| 简单详情抽屉 | `TyDrawer` | 重复手写 antd Drawer 封装 |
| 多 tab/缓存抽屉 | `TyDrawerUltra` | 页面内手写复杂 tab 抽屉 |
| 空态/错误态/未开通 | `TyEmpty` | 每个页面单独画空态 |
| 时序指标图 | `TimeSeriesChart` | 手写复杂时序图 |
| 热力图 | `HeatmapChart` | 手写二维热力和刷选逻辑 |
| D3 树状拓扑 | `TyFlow` | 从零写 D3 树 |
| 数据导出 Excel/CSV | `TyExportData` | 手写 xlsx 导出逻辑 |
