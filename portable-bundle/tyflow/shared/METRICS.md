# Tyflow 效果度量聚合

单个 `RETRO.md` 里的指标是孤立的，无法形成基线或看趋势。本文件把每次需求复盘的关键指标**汇总到一处**，让"降本提效"可被量化、可向团队和管理层展示。

## 维护规则

- 每完成一次需求复盘（`RETRO.md`），**必须**把效果度量追加为下表一行（这是复盘的收尾动作之一，不可省略）。
- 数值取自该需求的 `RETRO.md`「效果度量」小节。
- 不确定或不适用的项填 `-`，不要编造。
- 季度/里程碑结束时看「基线趋势」小节，判断工作流是否真的在提效。

## 基线趋势（定期人工汇总）

随着样本积累，在此记录滚动平均，作为"工作流是否提效"的客观依据：

| 周期 | 需求数 | 平均耗时 | 平均人工确认次数 | 平均 AI 采纳率 | 平均复用/新增比 | 平均验证失败次数 | 备注 |
|------|--------|---------|----------------|---------------|----------------|----------------|------|
| （首个周期待积累） | | | | | | | |

关注信号：

- **AI 采纳率持续偏低** → 输入质量或信任等级有问题（见 `WORKFLOW.md` AI 失效模式）。
- **人工确认次数居高不下** → 流程过重或理解确认环节没做好。
- **复用/新增比偏低** → 组件复用没落实，重复造轮子。
- **验证失败次数走高** → 实现质量或测试用例覆盖有问题。
