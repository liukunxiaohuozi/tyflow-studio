# 项目级知识（projects/）

每个项目一个子目录，存放**只属于该项目、不该升到全局 `RULES.md`** 的经验。当前核心是错题本 `LESSONS.md`。

```
shared/projects/
  <project>/
    LESSONS.md   # 项目级错题本：反复出现 / 被纠正 / 易复犯的问题
```

## 三层经验如何归位（重要）

| 经验类型 | 落点 | 说明 |
|---|---|---|
| 全局通用、跨项目都成立 | `shared/RULES.md` / `DECISIONS.md` / registry | 影响所有项目的硬规则 |
| **只对某项目成立** | **`shared/projects/<project>/LESSONS.md`** | 项目特定字段陷阱、组件用法、接口语义、构建/测试坑 |
| 纯一次性、不会复发 | 需求目录的 `RETRO.md` | 随需求归档即可 |

> 这一层填补了「全局规则太通用」和「需求复盘会归档」之间的空档——让项目特定的纠正信息有家可归，且后续 AI 开发该项目前会主动读到。

## 写入门槛

与 `RULES.md` 一致：**同类问题重复出现 ≥ 2 次，或属于「明显容易复犯」的坑**，才写进 `LESSONS.md`。一次性、偶发、不影响后续的，留在需求 `RETRO.md`。

## 谁读、谁写

- **读**：Step 4 识别到目标项目后、每次执行前检查时，AI **必须先读**对应 `LESSONS.md`，把相关条目当本次开发的约束。
- **写**：Step 18 复盘时，按门槛把项目特定问题登记/更新到 `LESSONS.md`。
- **升级**：同一条反复命中 → 在「状态」列升级为硬规则（写入 `RULES.md`）、补测试用例、或降相关操作信任等级（`TRUST.md`）。
