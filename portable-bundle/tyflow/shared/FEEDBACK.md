# Tyflow 工作流反馈簿（FEEDBACK）

> 收集**对工作流 / 门禁 / 规则本身**「行不通、别扭、反复造成阻碍或被绕过」的反馈，用来迭代 Tyflow 自己。
> 区别于需求级 `requirements/<id>/ATTEMPTS.md`——那记的是某个**技术方案**的受阻；这里记的是**流程层面**的问题。

## 何时记一笔

- 某个门禁 / 步骤 / 规则在实际开发中**反复造成阻碍**或被绕过。
- 某条规则明显**不合理 / 自相矛盾 / 与现实脱节**。
- 工作流缺一个环节，导致同类问题反复发生。
- AI 发现"按工作流这样做行不通"，且不是单次需求的偶发问题。

## 处理约定

- 反复出现（≥ 2 次）或影响面大的，应在复盘时提出修改 `WORKFLOW.md` / `RULES.md` / `PERFORMANCE.md` 等的建议。
- 采纳后在「处理状态」标记，并在对应文件落地；驳回也要写原因，避免反复提同一条。
