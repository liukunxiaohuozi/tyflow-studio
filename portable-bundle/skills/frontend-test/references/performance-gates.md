# B 端性能观察与项目预算

普通 change 先观察，稳定后告警，项目批准预算后才阻断。无限请求、页面卡死、崩溃、核心操作无法完成或持续资源增长导致不可用，可直接作为功能/稳定性问题阻断。

## 固定条件

绑定生产构建、sourceSnapshot、浏览器、OS、字体、DPR、视口、locale、timezone、CPU、网络、缓存策略、后端身份和数据规模。条件不可比时不做基线退化结论。

## 基线形成

- 单次变更观察：预热 1 次，再采集 3 次有效样本；使用中位数，只观察，不形成基线。
- 临时基线：至少 3 次独立运行，每次预热后采集 5 次有效样本；总样本不少于 15，覆盖至少 2 个不同时段。
- 正式参考基线：至少 5 次独立运行，总样本不少于 25，覆盖至少 3 个工作日；主要指标波动率不高于 15%。
- 波动率超过 15% 时不得形成正式基线；继续采样并检查环境、后端、网络、缓存和数据。
- 构建方式、主要依赖、浏览器、环境或数据规模明显变化后重建基线。

项目可要求更多样本，但不能低于单次观察的预热和 3 次正式测量。

## 分类退化候选

| 指标 | 候选条件 | 默认处理 |
|---|---|---|
| 页面加载、路由、列表查询、异步操作 | 中位数相对变慢 >25% 且绝对增加 >500ms | 首次观察；两次独立复测仍超过则告警 |
| 点击、输入、切 Tab 等即时反馈 | 中位数相对变慢 >30% 且绝对增加 >100ms | 首次观察；两次独立复测仍超过则告警 |
| 请求数量 | 新增同参数重复请求，或增加 >2 且 >20% | 告警；无限请求/请求风暴阻断 |
| 路由 JS gzip | 同时增加 >200KB 且 >10% | 告警；公共依赖升级单列 |
| 内存/资源 | 10 次开关后增长 >30%，或连续 3 个检查点单向增长且不回落 | 告警；稳定导致卡死/崩溃时阻断 |

候选数值不是所有项目的硬预算。数值退化只有在同一版本的两次独立复测均成立后升级为告警。只有项目已批准预算且复测仍超标，或已经造成明确不可用，才阻断。

## Web Vitals

采集 LCP、INP、CLS 及实验室加载指标，区分实验室与真实用户数据。LCP ≤2.5s、INP ≤200ms、CLS ≤0.1 是参考目标，不是观云所有页面的通用 change 硬门禁。由项目为指定路由、设备和 profile 批准后才生效。

## 归因

分别保存端到端耗时、接口等待、前端处理、渲染和资源阶段。后端或共享环境变慢仍是用户体验风险，但不能错误归因给前端变更。首次异常、复测结果和所有样本都保留；只保留最好一次属于证据不完整。

## 输入输出

`b2b-gates.mjs` 可从 `gate-input.json` 的 performance 对象计算基线状态和候选退化。每个 observation 至少包含 metricType、current、baseline 和 evidenceRefs；耗时使用毫秒，包体使用 KB，请求和检查点使用整数。
