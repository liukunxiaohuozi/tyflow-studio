# Architecture
The renderer has no Node APIs. Its context-isolated preload exposes only the typed StudioAPI contract; every main IPC call verifies the sender/frame and validates input. Imported previews use separate sandboxed sessions, no preload or network, and can navigate only within known imported HTML pages.

Main service owns an explicit task state machine and a TaskQueue (1–4 slots, default 2). Controllers are keyed by task. The same original directory is serialized; isolated tasks execute in distinct worktrees. Immutable development snapshots identify each task directory/branch. Stage results (last 50 runs) and bounded logs (last 2000 entries) survive restart, including an explicit stopped state for interrupted queued work. Checks finish at waiting-review; startup is explicit. Human acceptance may use an existing runtime after the user's review. Delivery is guarded against duplicate acceptance.

Workspaces use a task-owned branch even when an existing branch is selected as the baseline. Original uncommitted code is not imported. Dependencies install independently with a lock/manifest identity marker; ignored local environment files are copied without logging contents. Failed/cancelled tasks retain their directory. Shared remote synchronization has a service-owned controller so cancelling one subscriber does not cancel sibling tasks.

Previews start on demand. Default mode stops previous Studio-owned preview processes and reuses a single sandboxed verification window with task/branch title. Multiple previews are optional with separate ports. External responders are never killed or silently treated as a task's server.

Store uses schema-versioned atomic JSON. Credentials are separately encrypted with the OS account via safeStorage. ZIP import rejects traversal, symlinks, duplicate/case-colliding files, encryption, unsupported content and oversize streams. File hashes identify package versions; adoption invalidates prior analysis, while running snapshots remain unchanged.

Git and Codex use argv arrays with shell=false. Known Windows npm shims resolve to their Node entry files. Development/tests use Codex workspace-write; planning uses read-only. After manual acceptance, the service commits the task workspace and pushes the selected development branch through the configured Git credential path; it does not merge or deploy. The configured local AI CLI still needs authentication and project-specific environment access.

Windows and macOS share React/Electron source; packaging runs on the corresponding OS. Command discovery includes macOS Homebrew/NVM/FNM/Volta paths and the configured CLI directory. Setup checks test login and executable compatibility before showing readiness.

UpdateManager consumes a versioned HTTPS manifest, or resolves it from authenticated GitHub release assets. It enforces architecture, byte size, SHA-256 and ZIP path/link bounds before native extraction. Downloaded versions install side-by-side in userData/updates/versions. app.relaunch selects the verified executable after all task activity ends; original launches redirect to the selected version. Previous executables remain available for rollback. Data is not downgraded or overwritten. Tokens are encrypted separately and stripped on cross-origin redirects. CI emits studio-version.json in each final package and a three-platform update-manifest.json, with native tests/smoke before publishing. macOS remains ad-hoc signed, without paid notarization.
