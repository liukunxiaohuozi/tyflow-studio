# TingYun Studio 0.3.4 — 内部试用

## 本次更新

- 企业微信通知：开发配置 → 完成通知，显式启用并保存群机器人 Webhook 后发送关键节点摘要。凭据本地加密，页面不回读；保存本身不发送，测试按钮由用户主动点击。
- 通知隔离与去重：网络/业务拒收不会使开发任务失败；切换项目验证不重复通知开发完成。摘要使用实际 Worktree 分支；代码推送通知不代表合并或上线。
- 阶段检查点与失败分类：展示环境、Agent、代码、测试、Git、Policy、中断原因及建议动作。只重试失败阶段，在基线和证据一致时复用已通过检查。
- 暂停与补充：不仅限 Bug，评估、开发、测试等关键阶段支持暂停并追加文字/附件；取消弹窗保持暂停。冻结需求范围不自动扩大。
- Agent 保护：无输出和总时长超时、异常退出/网络失败识别；保留修改，用户确认后再恢复。模块拆分为 Workflow、Agent、Test、SCM、Issue、Notification、Evidence、Policy。
- Windows 退出回收：关闭客户端前等待自有进程树终止，避免验证服务残留占用端口和工作区。

## 同事如何测试更新

已有 0.3.x：开发配置 → 客户端更新，GitHub 仓库填写 liukunxiaohuozi/tyflow-studio，保存后点击“检查新版本 → 下载更新 → 启用更新并重启”。启用前需要完成或停止执行/排队任务。也可以开启“启动时检查新版本”，正常退出再启动后查看提示。

私有仓库需要本地填写有对应仓库读取权限的更新 Token。业务 GitLab 凭据、禅道凭据、企业微信 Webhook 与更新 Token 是不同用途，不混用。

首次安装：下载对应平台/芯片的 portable ZIP，完整解压后启动。macOS arm64 对应 Apple 芯片，x64 对应 Intel；内部包未做 Apple 公证，首次打开可能仍需系统安全确认。配置和任务使用当前 OS 用户的数据目录，不随 ZIP 分享。

通知试用：内部测试群添加群机器人，Webhook 只填到本机配置，保存后点击“发送测试通知”并到群核对。选择需要通知的节点；任务详情仍在执行人本机，没有新增共享后台。

## 验证边界

本地回归、隔离通知 sink、Windows Electron/IPC 验证已执行。CI 会在 Windows/macOS 分别执行回归、打包和启动烟测，全部通过且三个包与更新清单齐备后才公开 Release。真实企业微信投递、同事 Mac GUI、真实 Codex 服务及业务项目环境仍需内部人工试用；不能把模拟传输或 runner 启动成功解释为全部业务验收完成。

本次不包含 GitLab MR、CI 平台接入、禅道状态回写、通知内容增强、发布后企业微信群自动广播或后台定时联网检查新版本。客户端更新仍为启动检查或手动检查，不强制更新。
