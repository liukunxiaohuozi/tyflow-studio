# 阶段恢复与 Provider 边界

## 本次交付范围

在现有任务、并行队列、冻结快照和三道硬闸上加入可持久化的子阶段检查点。旧任务兼容；没有新检查点的旧记录不推断为已通过。客户端启动只标记中断，不自动重放 Agent、提交或推送。

## 内部职责

| 模块 | 实际入口 | 职责 |
| --- | --- | --- |
| Workflow Engine | src/main/workflow/engine.ts、recovery.ts | 队列、四阶段调度、检查点、结果复用、重启恢复、执行历史 |
| Agent Provider | src/main/providers/agent.ts、agent-schemas.ts | Codex 版本能力探测、登录、执行、结构化输出、超时与异常 |
| Test Provider | src/main/providers/test.ts | frontend-test / test-engineer 调用、工程命令、用例级复用、证据和业务文件保护 |
| SCM Provider | src/main/providers/scm.ts | Git 查询、同步、分支准备、差异、提交与推送 |
| Issue Provider（已下线） | src/main/providers/issue.ts | 仅保留历史实现供将来参考；客户端不再组装、暴露或调用 |
| Notification Provider | src/main/providers/notification.ts、wecom.ts | 通知资格、桌面及企业微信通道、持久化去重和失败隔离 |
| Evidence Store | src/main/evidence.ts | 导入截图/附件资源管理、脱敏 JSONL 日志、命令/测试结果索引、原子结果文件、SHA256 和路径校验 |
| Policy Engine | src/main/policy.ts | 操作权限、需求追踪、差异审查、证据硬闸、结果身份 |

StudioService 保留任务入口、项目配置、工作区/预览生命周期和模块组装；不再直接实现 Codex 调用或专业测试循环。Agent、SCM、Policy 有可替换的接口入口；禅道关联与配置已下线，不再组装 Issue Provider，旧数据只作兼容保留。SCM 使用 Git 协议，可服务 GitHub/GitLab 仓库；不是新增 GitHub/GitLab 平台 API。0.3.4 接入企业微信群通知：本地显式启用和加密保存 Webhook 后发送，默认关闭；钉钉仍仅保留 adapter seam。

## 检查点

- 评估：远程同步、目标版本、Agent 评估结果。
- 开发：需求追踪硬闸、分支/独立工作区、依赖安装、Agent 实施、代码差异硬闸。
- 测试：执行身份与环境、每条工程命令、测试 Provider 执行、每个批准用例。
- 验证：启动与运行验证（不能用旧结果替代活进程检查）。
- 交付：提交与远程推送；本地 commit 先持久化，推送重试沿用同一 commit。

每个检查点记录状态、尝试次数、复用次数、输入指纹、起止时间、结果路径/哈希和失败信息。每次阶段尝试仍保留 runs 历史；脱敏日志单独落盘并轮转，不只依赖页面最近 2000 条。

测试 Provider 生成的截图、trace 等文件仍在任务项目目录中，结果索引保存其路径与内容哈希；不擅自搬走或删除。附件管理和检查点结果归 Evidence Store 组装。删除项目中的原始证据会使对应复用失效，而不是只看旧的“通过”文字。

## 恢复规则

1. 重试从失败阶段继续，不重新走需求录入或需求评估。
2. 已通过命令/用例在同一代码、计划、Skill、补充信息和本地运行配置下复用；文件证据再次校验，缺失/篡改不复用。
3. 代码、忽略的 .env 文件、依赖标记、计划或上下文变更会使相关指纹失配。新增测试文件造成代码基线变化时，保守重验，不跨基线搬运通过结论。
4. Agent 开发结果按修改后的代码指纹保存。差异硬闸失败但代码未变时，不重复调用已经完成的开发 Agent。
5. 推送失败只重试交付，不调用开发/测试 Agent，不再创建第二个 commit，不强制推送。
6. 主动“修复并重测”是明确的新开发尝试，原测试检查点失效。
7. 外部后端、账号权限和数据可能变化，不能仅凭本地指纹证明它们保持不变；真实环境仍需人工验收或重新执行相关验证。

## 追加信息

评估、开发、测试、启动和排队中可“暂停并补充”。暂停会停止当前进程，保留已有修改，不回滚文件；取消弹窗不会恢复执行。确定后从当前阶段新开一次 Agent 调用，不是恢复旧的 Codex 会话。

待确认计划、待测试和待验收也有追加入口。未执行的计划收到补充后退回草稿，必须重新评估确认；已冻结任务仅追加上下文，不扩大批准范围。正在 Git 提交/推送时不能补充或中断，须等待其完成或失败，避免外部操作重复/状态竞争。

## 超时和失败分类

- 环境：缺命令、登录失败、缺测试 Skill、项目目录错误等。
- Agent：异常退出、结构化结果错误、网络中断、无输出/总时长超时。
- 代码：Agent 明确报告开发检查失败或阻塞。
- 测试：命令/用例失败、覆盖不足、证据无效。
- Git：分支身份改变、同步、提交 hook、认证或推送失败。
- Policy：需求追踪、差异范围、测试修改业务文件等硬闸。
- Interrupted：主动暂停/停止、客户端关闭。

界面显示失败码、检查点、影响范围和推荐动作。默认 Agent 无输出 3 分钟停止，单次总上限 30 分钟；开发配置可调整。原始 stdout/stderr 字节活动会刷新无输出计时，即使尚未形成完整日志行。超时/断网不自动重放有副作用的调用，须由用户确认重试。

## 当前边界

这是一轮内部模块拆分，不是插件市场或远程多 Agent 平台。未新增外部 Issue 写操作、GitLab MR/CI 或自动部署能力。Windows 上验证了恢复与 Electron/IPC 流程；真实 macOS GUI、签名安全提示及真实 Codex 网络中断仍需目标机器试用。0.3.4 下载包以 Release 发布结果为准；源码提交不会替换用户正在运行的客户端。
