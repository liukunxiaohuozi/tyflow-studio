# 企业微信通知（本地源码）

## 需求与边界

Oracle：本轮用户明确“GitLab；准备企业微信测试群，先完成通知，再逐项接 PR/MR、CI、禅道回写；权限信息通过本地配置填写”。通知必须独立于任务执行，不能借本轮授权操作业务仓库或禅道。当前不做群内交互、共享看板、任务链接服务器或 MR/CI 自动操作。

“开发完成”表示进入待测试/待人工验证，不代表已经验收。“必要检查完成”表示待验收，不虚称所有自动化测试已经完成。“代码成功推送”需要实际 pushedAt，不代表 MR 已创建、已经合并或已经上线。任务详情仍在执行人的本机，群成员不能通过摘要直接访问他的本地数据。

## 本地配置

1. 在内部测试群创建“自定义消息推送/群机器人”，由创建者复制 Webhook。入口以企业微信客户端实际版本为准。
2. Studio → 开发配置 → 完成通知，启用任务通知和企业微信测试群通知。
3. 在密码框填写 Webhook，选择需通知的节点并保存。Webhook 仅存当前 OS 用户的 safeStorage 加密凭据文件；普通配置只存启用状态，页面回读只得到 hasSecret。
4. 主动点击“发送测试通知”，到测试群核对。保存本身不会发送；未保存时不能测试。HTTP 200 不是成功，服务返回 errcode=0 才提示接收确认。
5. 留空保留旧凭据；“清除”并保存才删除。不在聊天、Git、Release 包、日志或文档记录真实 Webhook。

腾讯官方提供的群 Webhook 获取指引：https://intl.cloud.tencent.com/zh/document/product/1254/78645?lang=zh 。群机器人而非智能机器人 API，不需要 Bot ID/Secret 或通讯录权限。

## 实现位置

- contracts / policy：兼容旧配置的可选 WeCom 开关、推送节点及密钥输入校验。
- service / vault：密钥保存、清除、显式测试与摘要脱敏。
- providers/notification：状态变化决定通知节点，窗口聚焦仅抑制桌面通知。
- providers/wecom-webhook：只允许官方 HTTPS 单 key 地址，无重定向、任意主机或请求参数扩展。
- providers/wecom：主进程 POST 文本、十秒超时、业务响应检查、摘要字节限制、本进程每分钟最多 18 次请求保护。
- index / preload / App：通道独立发送；通知失败单独提示，不修改任务状态或重复开发。
- SettingsView：复用完成通知页，不新增团队后台。

## 数据与恢复

发送摘要含节点、任务名、项目名、执行人、分支、任务编号；不含需求正文、日志、代码、截图、文件路径。任务名仍属于业务信息：只给有权限的内部群，任务标题本身也不要填写秘密。配置内已知密钥做脱敏，不能承诺识别用户写入标题的全部未知秘密。

本地 userData/notification-receipts.json 存事件 SHA-256、时间、sending/sent/failed，无明文 Webhook 或任务正文。事件由目标群、任务、节点、计划版本、对应阶段执行轮次、失败时间和交付提交组成，同一事件并发/重启后不重复发送。切换验证窗口和重新启动预览不形成新的开发完成事件。先持久化 sending 再发网络；记录损坏时通知停用，开发仍可继续。分支摘要使用实际任务 Worktree 分支，非基线分支。

断网/超时可能已送达，不能保证网络的 exactly-once；因此不自动重试 uncertain/failed，先查看群。新的真实执行轮次可形成新事件。需要检查连接时可主动再发固定测试消息，不重放任务内容。限流仅本机保护，不协调多台电脑共用同一机器人；建议测试期每位测试者用自己的机器人，或保持低频。

## 验证计划与实际服务缺口

R3（凭据和外部消息写入）：必须隔离测试群。单测覆盖地址校验、发送协议、业务拒绝、超时、脱敏与字节界限、并发/重启去重、损坏记录、限流、保存/保留/删除凭据和工作流隔离。真实 Electron smoke 走 UI→preload→IPC→service→OS vault，HTTP 注入独立 sink，禁止真实消息外发。

单测和 sink 不证明真实企业微信群可收消息。还需要配置者主动发送测试消息并人工核对群，然后在受控试用中观察一个任务完成/失败通知。Windows 检查不等同 macOS 验证。当前构建源码不等同替换本地安装包或发布 GitHub Release。
